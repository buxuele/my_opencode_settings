# 迁移清单

新机器上要跑出同样效果，除了安装仓库文件，还需要下面这些外部条件。

## 一、必装软件

1. opencode 本体，建议与作者同版本，配置格式随版本变化。
2. node 与 npm，插件依赖需要，作者环境是 node 24 与 npm 11。
3. sqlite3 命令行，偏好整理指令要读会话数据库。
4. Python 3.11 以上，部分技能脚本使用。

## 二、必配环境变量

写进 ~/.zshrc，值不要进仓库。

1. GITHUB_TOKEN，推送仓库与查询接口用。
2. PATH 里需要包含 ~/.local/bin，chrome-devtools-mcp 装在这里。

## 三、可选外部程序

opencode.jsonc 里引用了两个 MCP，缺任何一个都会在启动时打印错误。用不到就把整个 MCP 配置块删掉。

1. chrome-devtools-mcp，装在 ~/.local/bin/chrome-devtools-mcp。
2. Chrome for Testing，作者路径是 ~/.local/share/chrome-for-testing/chrome-mac-arm64/Google Chrome for Testing.app。系统 Chrome 也能用，但没有独立 bundle id，无头实例会抢 Dock 激活。
3. mac-mcp，作者路径是 ~/code/py_apps/mac_mcp/server.py，依赖同目录下的 venv。这是自建工具，不在任何包管理器里。

## 四、安装后验证

1. 启动 opencode，确认没有配置解析报错。
2. 执行 /what 这类自定义指令，确认指令已加载。
3. 让助手调用一次技能，确认 skills 已识别。
4. 新建会话看标题是否自动生成，确认插件生效。
5. 让助手打开一个网页，确认走的是无头截图而不是弹默认浏览器。

## 五、常见问题

1. 插件首次加载报找不到模块：进对应插件目录执行 npm install。
2. 配置里的路径没有替换成功：确认 install.sh 顶部的 AUTHOR_HOME 与源配置一致。
3. 模型不可用：模型名与供应商由 opencode.jsonc 决定，需要本机已登录对应供应商。密钥不要写进配置，交给 opencode 的 auth 流程。
