调研对象：$ARGUMENTS

如果没有给出对象，就把当前工作目录里的项目当作调研对象，先读它的 readme、开发记录与代码，确认它到底是什么，再动笔。

调研必须覆盖这些方面：起因、发展历史、创始人、市值、用户规模。对象是个人项目而非公司时，市值改为收入或融资情况，查不到就写公开资料未载。

事实要求：

1. 涉及融资、估值、用户数、发布时间、人物履历这类会变化的内容，一律先用 websearch 或 webfetch 核实，不许凭记忆下结论。
2. 每条关键事实后面给出可点链接来源。来源冲突时两边都列，不替人裁决。
3. 查不到就明确写公开资料未载，严禁编造年份、奖项、版本号和人物轶事。

写作要求：

1. 全中文，零 emoji。
2. 用叙事推进，按时间线讲清楚起因、转折和结果，不要写成干巴巴的条目堆叠。
3. 禁止加粗，禁止英文双引号，正文用中文引号，说明性正文不用括号。
4. 数字要具体，能核对，不写大幅增长这类空话。

落点：直接写在当前项目根目录，文件名用中文，例如 项目调研.md。不新建目录，不往 docs 里塞。交付时报告行数、字符数和来源条数。
