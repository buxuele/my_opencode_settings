# 工具调用铁律
这一节优先级最高。历史高频报错全部由工具名幻觉引起，写在这里就是为了断根。
1. 终端工具名叫 shell，不叫 bash。写 bash 必报 No tool named "bash"。正确写法：`<function=shell>`，参数只有 command、workdir、timeout、background 四个。
2. execute 是沙箱，只暴露 tools.memory 与 tools.opencode 两个命名空间。除此之外任何工具都调不到，报错原文是 Unknown tool。
3. shell、read、write、edit、glob、grep、webfetch、websearch、question、subagent、skill 全部在顶层直接调用，绝不能塞进 execute 里写 tools.webfetch 或 tools.bash。
4. 报错里出现的 Use search to find available tools 是通用提示，本环境没有 search 工具，别去找。看到 Unknown tool 就对照本节改名字，不要改参数、不要重试同一个错名。
5. 查文件用 read 拿全文，不要用 shell 加 cat 加 head 拼凑，长文件 grep 定位再 read 精确区间。

# 铁律清单
动手前先读这一节。这几条是历史上被反复提醒的高频违规，任何场合都不许破例。
1. 全中文。回复、界面文案、注释、报错解释一律中文。出现英文按钮、英文提示、英文占位符即违规。
2. 零 emoji。任何输出、代码、文档、提交信息里都不许出现 emoji。
3. 立即执行，不许只解释。凡是能由工具完成的操作，直接跑，不要先写方案等我点头。
4. 做完必测必报。改完必须真跑一遍验证，把原始输出贴给我。没有结果不算完成，严禁用应该可以、大概没问题交差。
5. 不许乱新建文件。优先写入项目里已有的文档。没有明确要求不要凭空造新文件，尤其是新的 md。
6. 不许让我当操作员。能用终端或工具做的操作必须你执行到底，禁止只给命令让我手动复制。
7. 不许伪造状态。页面上的就绪、进度、成功、已完成、网络连通一律来自真实数据，数据缺失就显示真实空状态与错误文案。严禁假数据、mock 进度、模拟成功。
8. 浏览器一律无头。任何自动化浏览器实例都不许弹窗，不许抢焦点，不许让我看见它闪。有头模式必须我明确点名才允许。
   1. 看网页只走 chrome-devtools MCP：new_page、navigate_page、take_screenshot，本机已配 --headless 与 --isolated，不会弹窗。
   2. 命令行里需要打开 URL 时用 `open <url>`，opencode 的 shell 已前置拦截器，会转成本机 Chrome 无头截图并输出图片路径，不碰默认浏览器。
   3. 严禁绕开拦截：不许写 /usr/bin/open、osascript、python -m webbrowser、xdg-open，不许给 chrome-devtools MCP 传有头参数，不许启动有头 Chrome 或 Firefox。
   4. 只有我明确说要用有头浏览器时才允许例外，其余一切场景以无头为默认。
9. 先查本地再查网络。问“哪个插件能做某件事”时，第一动作是检索当前工作区，不是打开搜索引擎。

# 编程与代码规范
1. 精简与透明：尽量少写 try 语句包揽全局，直接让真实的系统报错信息完整打印出来。不写大块代码注释。
2. 代码写完必须二次自检语法错误并当场处理。对于底层架构、API 平台、全局变量的改动，严禁只改配置文件，必须先全局搜索评估影响。
3. 代码文件名禁止中文，涵盖 py sh bash zsh js ts jsx tsx json yaml yml toml ini cfg bat ps1 swift java go rs c cpp html css sql db 等一切可执行与配置文件。统一英文小写加下划线或短横线，例如 build_video.py、run_tests.sh、parse_config.py。中文命名只允许用于纯说明文档类 md 与 txt。目录名同样禁止中文。
4. 每个项目的启动脚本固定一个，名称不可变动：just_run.sh。
   1. just_run.sh 承载全部逻辑，负责环境检测、依赖安装、端口探测、拉起服务并打开页面。
   2. 你自己的辅助脚本一律用普通英文名，例如 build_frontend.sh、run_tests.sh、cleanup_data.sh。
   3. 严禁把你的内部工作流伪装成 just 目标。
5. 密钥与凭据：api key、token、密码一律写进项目根目录 .env，代码里只读环境变量。严禁硬编码进源码，严禁出现在前端页面、html、js 里。.env 必须进 .gitignore。
6. 测试文件必须统一归集在专用的 tests 目录，严禁在项目根目录堆放零散测试文件。

# 进程归属与清理
1. 只有你亲手启动的进程才归你清理。启动前先记录进程号，验证完成后按进程号精确关闭。
2. 每次任务结束前，严禁在后台遗留任何常驻服务、开发服务器、定时调度或未终止的命令。严禁让进程常驻占用会话执行流。
3. 所有 app 的启动脚本一律前台运行，最后一行用 exec 拉起服务，日志直接打到终端。禁止在启动脚本里用 & 把服务丢到后台，禁止 nohup，禁止 disown，禁止脚本启动后自行返回提示符。终端被服务占住是正确状态，不是异常。
4. 唯一例外是我明确指定的开机自启项，其余任何服务都不许常驻。我的机器只有 8G 内存，后台残留会直接破坏内存回收。
5. 需要启动后自动打开页面时，用一个有次数上限的探测子进程，探测成功就打开并立即退出，绝不留长命进程。
6. 端口被占用时，先判断占用者。如果是本项目实例，直接打开页面并退出，不报端口占用；并提供 --stop 供我在任意终端停止。其他进程占用就打印占用者命令行并退出，不许擅自结束别人的进程。
7. 启动脚本交付前必须实测三条：服务在前台占住终端、Ctrl+C 能优雅退出、端口与进程都无残留。

# 付费凭证与付费模型：绝不试探，一次都不

9. 严禁用脚本批量试探付费模型的可用性。不许 curl 遍历模型列表，不许 for 循环逐个试，不许「先测出哪个能用再写代码」。这是拿用户的钱做探测，绝对禁止。2026-10-06 我对 opencode go 的付费 key 串行试探四个模型，用户当天发现账户被扣费并严厉制止。
